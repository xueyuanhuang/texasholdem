# UAT Checklist (Human Acceptance)

本清单用于人工验收 A/B/C 三个窗口改动是否可用。

## 0. 验收准备

1. 启动本地服务：
```bash
cd /Users/xueyuanhuang/Projects/texasholdem
python3 -m http.server 8080
```
2. 浏览器打开 `http://localhost:8080`
3. 建议开一个无痕窗口，避免旧缓存干扰

---

## 1. A 窗口（数据层）验收

1. 首次打开页面不报错，能正常进入界面。
2. 随便新增一条数据（例如加一个玩家），刷新页面后数据仍在。
3. 进入浏览器 DevTools -> Application -> IndexedDB：
   - 存在数据库 `texasholdem_db`
   - 存在 `app_state` store
   - 存在 key `texasholdem_data`

通过标准：数据可持久化，刷新不丢失。

---

## 2. B 窗口（锦标赛链路）验收

1. 比赛页选择 4-6 名玩家，进入实时对局。
2. 补码按钮按规则可用/不可用（超过限制后禁用）。
3. 连续淘汰到只剩 1 人时自动结束并回到排名确认。
4. 保存锦标赛后：
   - 历史页出现记录
   - 排行榜分数有变化
   - 刷新页面后记录仍在

通过标准：从“开始对局”到“保存比赛”全链路可走通。

---

## 3. C 窗口（现金局/设置/历史）验收

### 3.1 现金局校验
1. 选 3 个玩家，默认每人 1 手买入。
2. 输入一个非法剩余筹码（如 `-1` 或 `12.5`）：
   - 出现“剩余筹码必须是非负整数”
   - 输入被回退
3. 修改 `每手筹码/每手价格` 为非法值（空、负数、字母）：
   - 校验区提示参数无效
   - 不显示转账方案
4. 输入一个平衡局（总剩余筹码 = 总买入筹码）：
   - 显示 `✅ 校验通过`
   - 显示转账建议

### 3.2 现金局排行榜
1. 保存至少两场可结算 Cash Game。
2. 打开历史页：
   - 顶部出现“现金局排行榜”，默认收起
3. 点击“展开”：
   - 按累计胜负分从高到低显示玩家
   - 每行显示累计分、参局数、平均分
4. 有暂不可结算或进行中的 Cash Game：
   - 不计入排行榜

### 3.3 设置页导入导出重置
1. 点击导出：
   - 文件名应含日期时间（`texasholdem_data_YYYY-MM-DD_HHMM.json`）
2. 导入错误 JSON：
   - 出现明确错误提示，不覆盖当前数据
3. 导入正确 JSON：
   - 显示导入成功，并显示场次统计
4. 重置数据：
   - 两次确认
   - 提示将删除的场次数
   - 重置后回到默认状态

### 3.3 历史页
1. 创建“同一天两场锦标赛 + 一场 Cash Game”。
2. 历史页同一天应展示：
   - `2 场锦标赛`
   - `1 场 Cash Game`
3. 展开后应看到两场锦标赛都在，不互相覆盖。

通过标准：现金局校验有效、导入导出重置可信、历史分组正确。

---

## 4. 10 分钟速验（最小通过）

1. 新增玩家 -> 刷新后仍在（A）
2. 跑完一场锦标赛并保存 -> 历史+排行榜有记录（B）
3. 跑一场现金局，看到 `✅ 校验通过` 和转账建议（C）
4. 导出 JSON 再导入 JSON，数据不丢（C）

以上四步都通过，即可判定本轮可发布测试。
